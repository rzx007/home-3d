# 73㎡ 两室一厅 · 第二间房的三种答案

一个用 **Three.js** 做的交互式 3D 家装网页。同一个 73㎡ 两室一厅户型，把「第二间房」这个变量
摆到台面上：**在家工作 / 朋友留宿 / 留给未来**——一键切换整屋家具布局，看同一面墙在不同生活方式里
扮演什么角色。

四种视角、开场从 2D 户型图长出整屋、时间滑杆驱动一天的光照、点房间看面积与家具清单。
**所有家具与贴图都是程序化生成**（零外部图片资源），同时预留了一条 Blender 预制 GLB 资产的替换通道。

---

## 快速开始

静态服务器即可，不需要构建、不需要联网（three.js 已 vendored 到本仓库）。

```powershell
cd <项目目录>
python -m http.server 8181
# 浏览器打开 http://127.0.0.1:8181/
```

或者：

```powershell
npx --yes serve -l 8181 .
```

> 必须走 HTTP 打开。直接双击 `index.html`（`file://`）会因为 ES module / importmap 的跨源策略加载失败。

## 界面与操作

**顶部**
- `第二间房`：三个方案一键切换，整屋家具随之重建（含客厅、餐厅、玄关的联动增减）。
- `视角`：立体剖视 / 正交俯视 / 1.35m 剖切 / 第一人称漫游，也可用键盘 `D T S W` 切换。
- `房间标签` 显示房间名与面积浮标；`灯光阴影` 关掉可提帧；`GLB 资产` 见下文。

**三种方案**
| 方案 | 第二间房 | 整屋联动 |
| --- | --- | --- |
| 在家工作 | 书房：升降桌贴北窗、工学椅、洞洞板、文件柜、书架、单人沙发 | 客厅 −单人椅 +边柜，餐厅 +1 餐椅，过道 +挂画 |
| 朋友留宿 | 客卧：1.5m 沙发床、茶几、衣柜、床头柜 + 台灯 | 客厅 +2 折叠椅，玄关 +行李凳，过道 −挂画 |
| 留给未来 | 儿童房：婴儿床、尿布台、成长尺、摇椅、玩具筐、爬行垫 | 客厅 +玩具收纳 +爬行垫，餐厅 +儿童椅，夜里留小夜灯 |

**时间滑杆**（底部）
0–24 点连续可拖，也可点 6 个预设。它同时驱动：太阳高度角与方位（6:00 日出、18:00 日落、正午 62°）、
太阳色温、天穹渐变、雾、曝光，以及 **18:00–07:00 之间台灯与吊灯自动亮起**（灯罩与灯泡的自发光材质同步点亮）。

**房间卡片**
点任意房间（墙、地面、家具都算）弹出面积 / 开间 / 净高、地面材料、门窗与**家具清单**；
再点一次空白处收起。左侧房间清单与右上卡片、左下迷你地图三者联动高亮。

**第一人称漫游**
点击画面锁定鼠标 → `WASD` 走动、`Shift` 快走、移动鼠标转头。墙体与家具都有碰撞（胶囊半径 0.26m），
门扇是**动态碰撞体**：对着门点击或按 `E` 开关，门通到哪就能走到哪。迷你地图上会画出你的位置和朝向。

**开场动画**
从 2D 户型图一笔一笔描出来开始：墙体按房间顺序升起 → 窗框门套弹出 → 家具浮起落位 →
相机从正俯视俯冲到立体剖视。太阳同时从 7:00 升到 10:00。点「跳过开场」或按空格可略过。

## 接入 Blender 预制 GLB 资产

页面默认使用**程序化建模**（打开就能跑）。要换成手工资产，生成 32 件 GLB 即可自动接管：

```powershell
blender -b -P blender/build_assets.py
# 或只做几件：blender -b -P blender/build_assets.py -- --only bed_double,wardrobe
```

脚本会：
1. 按 `src/assets.js` 的 `ASSET_MANIFEST` 生成 32 件低面数模型（立方体 + 8~12 边圆柱 + 一段倒角），
   颜色取前端同一套色板（sRGB→线性转换后写入 Principled BSDF）；
2. 每件单独导出 `assets/glb/<name>.glb`，**模型原点在底面中心**；
3. 重写 `assets/glb/manifest.json`（`present: true` + 生成清单）。

刷新页面，顶栏勾选 **GLB 资产**，状态栏会显示「GLB 资产 N/32 件已替换」。
运行时 `applyGlbSwap()` 会把同名程序化家具整体替换为 GLB，并把原点自动归一到「底面贴地、XZ 居中」
（`normalizeOrigin` 还会在高度比例明显不对时按目标尺寸自动校正），所以无论建模时原点在哪都能正确落地。
碰撞盒沿用清单里的目标尺寸，替换后依然有效。

> 未生成 GLB 时前端只读一次 `manifest.json` 就跳过，不会产生 32 个 404。

## 技术要点

- **墙体开洞不用布尔**：把每面墙拆成沿墙方向 + 高度的实体片段（`wallPieces`），洞口自动生成
  窗下墙 / 窗上墙 / 门头梁。同一套片段逻辑同时用于 3D 建模、2D 图纸墙体涂黑、踢脚线与卫生间墙砖。
- **两个裁剪面**：立体剖视用**局部裁剪面**只切墙体与门扇（家具保持完整，像实体建筑模型）；
  1.35m 剖切图用**全局裁剪面**把整栋含家具一起切开，配图纸底色 + 填充光，读起来像剖面图。
  两个裁剪面在启动时就挂到材质上（`constant = 100` 即不切），GPU 程序一次性编译完，切视角不卡。
- **天花做两份**：一份只投影不显示（`colorWrite: false`）常驻，保证白天室内光几乎全部来自窗口、
  地上会出现窗洞光斑；另一份只在漫游视角显示。
- **软阴影**：three r186 已移除 `PCFSoftShadowMap`，改用 `VSMShadowMap`（两遍模糊，`radius 2.6`、
  `blurSamples 12`）。吊灯用 SpotLight 投影，台灯用 PointLight 不投影——灯罩里就是光源，
  灯罩一旦投影会在自己脚下烧出一个黑盘。
- **程序化贴图**：木纹按真实尺寸排 UV（1m 一次平铺，板宽 20cm），并从高度图用 Sobel 推导法线贴图，
  所以板缝、布纹、瓷砖缝在阳光下有真实起伏；相邻房间的地板缝隙自然对得上。
- **降 draw call**：静态 mesh 按材质烘焙合并（`optimize.js`），实测 2066 → 700 左右。
- **相机过渡按墙钟时间**（1.15s）而不是帧率累加，所以高刷屏和低帧机器表现一致。
- **HUD 全部是 DOM**，房间标签用 DOM 投影而不是 Sprite，文字永远像素级清晰，样式直接吃设计系统。

## 验收工具

`tools/` 下是用 CDP 驱动真实 Chrome 的小工具（Node 22+ 自带 WebSocket，无第三方依赖）：

```powershell
node tools/headless-check.mjs  http://127.0.0.1:8181/index.html   # 跑一遍 4 视角 × 3 方案 × 3 时段，报告异常
node tools/shots.mjs           http://127.0.0.1:8181/index.html   # 抓 10 张验收截图到 shots/rXXXX/
node tools/inspect-scene.mjs                                      # 列出场景里的对象/材质/裁剪面状态
node tools/section-diag.mjs                                       # 剖切视角取景与背景诊断
```

当前状态：**0 未捕获异常、0 console 错误**；渲染 draw call 约 735（剖视白天）/ 774（剖切）/ 655（漫游）。

## 已知限制

- 户型是按国内常见紧凑两室一厅构造的**示意户型**，不是某个真实楼盘的原图。
- 卫生间 3.52 ㎡、厨房 3.96 ㎡ 偏紧凑，属于该面积段常见的取舍。
- 漫游时没有做楼梯/多层、没有门的物理推挡（门是直接开合动画）。
- GLB 资产脚本已备好但**仓库里不含生成结果**（本机未安装 Blender），所以页面默认走程序化建模。
- 窄屏（<1080px）会自动隐藏左右面板，只留顶栏与时间滑杆，保证 3D 视野。
